# 一次性事件的消费时机

一次性订阅在过滤条件通过后、任意用户处理回调执行前取消订阅。
立即处理和延迟处理采用同一消费时机；连续推送两个事件不会把同一个延迟回调排队两次。

过滤器返回 false 时保留订阅。运行一次性订阅的过滤器期间，该订阅暂时保留给当前推送，
过滤器重入推送事件不会再次调用它。如果过滤器取消并重新订阅，同一次推送不会消费新订阅。
回调内重新订阅同一方法是一个新订阅，允许它处理随后的或重入的事件。

派发仍使用本次筛选完成的回调快照；回调开始后取消其它已筛选回调，不撤销本次派发。
新订阅只参与之后开始的推送；已经失效的 Callable 会跳过。
普通订阅仍可重入，业务代码负责防止无限递归。
本次不更改既有按对象与方法生成元数据键的方式，带不同绑定参数的 Callable 身份问题另行处理。

自动回归：运行 `res://addons/godot_core_system/test/unit/event_once_checks.tscn`。
覆盖回调自身重入、高优先级回调重入、过滤拒绝/接受/重入/替换、延迟派发与重新订阅。
人工验收时检查业务中是否依赖一次性回调执行期间仍能查询到订阅的旧行为。
